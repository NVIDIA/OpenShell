# Supervisor middleware troubleshooting

Use this reference when the deployment registers supervisor middleware or a
sandbox policy attaches it through `network_middlewares`. Start with gateway
reachability and compute-platform checks in the [main skill](../SKILL.md).
Use installed CLI help for command syntax and the published
[gateway configuration reference](https://docs.nvidia.com/openshell/latest/how-it-works/gateways/configuration)
for registration settings.

## Collect diagnostics

For operator-run supervisor middleware, inspect `[[openshell.supervisor.middleware]]`, service reachability, and both gateway and supervisor logs:

```shell
rg -n 'supervisor|middleware|grpc_endpoint|tls_ca_cert_path|audience|allow_insecure_transport|max_payload_bytes|timeout|gateway_jwt' /etc/openshell/gateway.toml
journalctl -u <middleware-service> --no-pager --lines=200
journalctl -u openshell-gateway --no-pager --lines=200
openshell logs <sandbox-name> --tail --source sandbox
```

## Startup and authentication

The middleware service must start before the gateway and be reachable from both the gateway and sandbox supervisors. Gateway startup fails if `Describe` is unavailable, peer metadata is missing, the protocol major is incompatible, a required capability is absent, a manifest exposes duplicate operation/phase bindings, the registration claims the reserved `openshell/` namespace, or payload and timeout limits are invalid. Current services receive `MiddlewareDescribeRequest` instead of an empty request; regenerate bindings when upgrading a service built before peer metadata. Supported bindings are `HTTP_REQUEST/PRE_CREDENTIALS`, `HTTP_RESPONSE/PRE_RETURN`, and `WEBSOCKET_MESSAGE/PRE_CREDENTIALS`.

Each HTTP binding selects its HTTP protocol with `http_protocol_version`: unset or `0` is HTTP protocol 1, the deprecated legacy protocol (`EvaluateHttpRequest` and `HttpResponsePreReturn.Evaluate`), which OpenShell 0.2.0 removes, and `2` is HTTP protocol 2 (`HttpRequestPreCredentials.EvaluateHttp` and `HttpResponsePreReturn.EvaluateHttp`). Registration fails for any other version, for `supported_http_body_modes` on a legacy binding, for an invalid or duplicate body mode, and for a service that requires `openshell.supervisor-middleware.http-v2` but advertises legacy HTTP bindings. Version 2 bindings list `BUFFERED` and `STREAM`, or no modes for a preflight-only binding, which may advertise a zero payload limit. Gateways and supervisors advertise `openshell.supervisor-middleware.http-v2` in their `Describe` request, so a service that serves both protocols returns version 2 bindings to them and legacy bindings to supervisors from 0.1.2 or earlier.

At startup the gateway logs a warning and emits a Medium OCSF configuration deprecation event for each registered service that still describes legacy HTTP bindings, then a summary that points to `openshell gateway upgrade-check`. The gateway describes services only at startup; restart it after a service changes protocol. Supervisors describe services again when their delivered service set changes, after a failed registry rebuild, and at the next policy poll after a contract failure. If any delivered service is unavailable when a supervisor starts, it runs with built-in middleware only, and every entry that uses a registered service follows `on_error` until the registry installs, except in the HTTP directions where the gateway described a version 2 binding (`http_request_protocol_version` or `http_response_protocol_version` on the delivered registration), which fail closed with `binding_not_described`.

When gateway JWT signing is disabled, supervisors preserve the legacy unauthenticated connector and do not request extension credentials. When signing is enabled, credential acquisition and verification failures are fail closed: check HTTPS trust and hostname validation, audience and issuer agreement, the token `kid`, gateway `RefreshSandboxToken` errors, and middleware logs. Changing a registration requires a gateway restart. A policy update can also fail before persistence if the selected implementation rejects its `network_middlewares` config.

## HTTP response failures

For response failures, distinguish a deliberate `middleware_denied` decision from `response_delivery_failed`. Before response commitment, they produce canonical 403 and 502 responses respectively. After commitment, OpenShell aborts without adding an error body, final chunk, or trailer, closes the connection, and emits a High `openshell.middleware.http_response_failure` finding with `commitment=after_commit` and the downstream framing. The head commits when the last body-inspecting stage starts its output. A policy reload ends the stages with `POLICY_RELOAD` at once; before commitment it closes the connection without any response, and after commitment it aborts, unless the client already received the whole body.

Version 2 response stages always fail closed. Check which body modes the preflight offered: a bodyless, partial (206, `Content-Range`, `multipart/byteranges`), content-coded, or `no-transform` response offers none; an HTTP/1.0 client request or upstream status line offers no `STREAM` (`TRUNCATION_UNDETECTABLE`); `text/event-stream` and `multipart/x-mixed-replace` offer no `BUFFERED` (`OPEN_ENDED`); and a declared length over the stage limit offers no `BUFFERED` (`OVER_LIMIT`). Selecting a mode that was not offered, or a `max_body_bytes` outside the offered limit, fails with `body_mode_not_permitted`. A version 2 `BUFFERED` stage has a 2-minute deadline from when it starts receiving the body, covering upstream reads, its exchange, and delivery of its output (`middleware_body_timeout`); body overflow is `buffered_input_over_capacity`. A version 2 `STREAM` stage has no total deadline and no size cap; it fails with `middleware_stall_timeout` when it accepts no input for 30 seconds while its output is not held back, or returns nothing for 30 seconds after input end. Upstream silence never ends a framed response, so server-sent events survive long gaps.

Legacy response stages keep 0.1.x behavior and `on_error`: each whole-body stage has its own fixed, non-resetting 120-second wall-clock deadline to accumulate the body, counted from when that stage starts receiving it (`whole_body_accumulation_timeout`), and an overflow is `whole_body_over_capacity`; under `fail_open` both release the original body. Legacy `STREAM_BYTES` is still offered on HTTP/1.0 and delivered close-delimited. Header-only stages preserve upstream body framing. Body-processing stages normalize framing and send a trailer exchange, including an empty trailer set, after the final body result. A stage that streams or replaces the body strips stale integrity headers such as `etag`, `digest`, and `content-digest`.

Response capacity failures return 502, not 503: when the supervisor's 32 middleware sessions are in use, fail-closed and version 2 entries fail with `middleware_session_capacity_exhausted`, while a chain of legacy `fail_open` entries delivers the response uninspected. A full work queue for legacy stages fails with `admission_exhausted` regardless of `on_error`. Both emit the same `openshell.middleware.session_capacity_exhausted` or `openshell.middleware.admission_exhausted` finding as requests, with `operation=http_response`.

A client that closes its connection after the response head, whose connection fails, or whose write fails ends the response at once: stages end with `DOWNSTREAM_DISCONNECT`, the session is released, the upstream connection closes, and a response that held a session records an Informational `downstream_disconnect` event. A close before the head is a half-close that ends the response after 30 seconds without upstream data or client writes (`response_half_close_idle_timeout`). Once the client sends a pipelined request, its close is noticed only at the next failed write.

## Request and WebSocket failures

At request time, distinguish attachment, binding selection, coverage, denial, and failure. Request middleware rejections return 403 `middleware_denied`, and failures return 403 `middleware_failed`. Exhausted middleware sessions or legacy work admission return 503 `middleware_failed` before the body is read and emit `openshell.middleware.session_capacity_exhausted` or `openshell.middleware.admission_exhausted`; `on_error` does not apply. A request whose body stops arriving for 30 seconds while request middleware inspects it ends with `408 Request Timeout` (`request_client_progress_timeout`); this also applies to legacy request stages, which had no such limit in 0.1.x. A version 2 `BUFFERED` request stage fails with `middleware_body_timeout` when receiving, evaluating, and forwarding the body takes more than 2 minutes, including the upload time. Output withheld for a `BUFFERED` stage, a legacy stage, body-aware policy, SigV4 signing, body credential rewriting, HTTP/1.0, or the forward proxy is limited to 4 MiB (`request_output_over_capacity`); a chain of only `STREAM` stages forwards an HTTP/1.1 body as it streams. A policy reload closes a request in progress without a response and ends its stages with `POLICY_RELOAD` at once.

Version 2 HTTP stages always fail closed and ignore `on_error`; a `fail_open` entry whose middleware serves only version 2 HTTP emits a Medium `fail_open_not_applied` configuration event when it first handles traffic. A stage that ends with `FAILED_PRECONDITION` fails with `middleware_cannot_inspect`. `UNIMPLEMENTED`, an undecodable message, or an unknown version 2 result is a contract failure for legacy and version 2 stages alike: it fails closed whatever `on_error` says, emits a High `openshell.middleware.contract_failure` finding, and the supervisor re-describes its middleware services at the next policy poll. The finding is rate-limited per service, binding, and contract failure kind: the first failure is reported at once, and later ones until the next policy poll arrive as one finding with `unmapped.suppressed_count`. A service missing the `HttpRequestPreCredentials` gRPC service shows up this way. A host-matched HTTP-only attachment can inspect the upgrade GET but does not join the WebSocket chain; the connection proceeds under either `on_error` mode and emits `binding_not_selected` coverage. A selected WebSocket stage receives text messages only. Binary messages pass under both modes, emit `unsupported_message_type` coverage, and consume a session sequence without an RPC.

An explicit `middleware_denied` result is always enforced. WebSocket preflight returns `INSPECT`, voluntary `SKIP`, or authoritative `DENY`; `DENY` rejects the upgrade before upstream contact under both `on_error` modes. A selected WebSocket or legacy HTTP stage failure follows the policy-local `on_error`: `fail_closed` blocks the HTTP request or closes the WebSocket, while `fail_open` bypasses only that stage and emits a detection finding. A fail-open per-message capacity failure bypasses that message without disabling the stage. A timeout, transport failure, stream closure, missing or invalid response, duplicate or regressed sequence, or other failure that makes an established WebSocket stream unreliable disables that stage for later messages on the connection and emits `openshell.middleware.websocket_stage_disabled`.

Confirm preflight, session-start, and session-end in service logs. OpenShell best-effort sends at most one session-end to each still-writable opened stage, including a preflight that terminates before session start; distinguish `MIDDLEWARE_DENIAL` from `MIDDLEWARE_FAILURE`.

WebSocket message sequences are allocated session-wide; each stage receives a strictly increasing subset, so gaps are valid when binary messages or other units are not delivered to that stage. Zero, duplicate, or regressed sequences are protocol errors. If a running supervisor cannot install a new registry, it preserves its last-known-good generation and emits a configuration failure event.

## Common failure patterns

| Symptom | Likely cause | Check |
|---|---|---|
| Authenticated middleware rejects gateway calls | Private CA or hostname mismatch, expected audience or issuer mismatch, stale/unknown `kid`, or malformed extension token | `tls_ca_cert_path`, registration `audience`, service verifier config and logs; fetch well-known metadata only through the already-trusted gateway TLS endpoint |
| Gateway fails after registering supervisor middleware | Service unavailable, invalid manifest, duplicate binding, reserved name, invalid payload/timeout limit, unsupported `http_protocol_version`, body modes on a legacy HTTP binding, or a service that requires `openshell.supervisor-middleware.http-v2` but advertises legacy HTTP bindings | Middleware service and gateway logs; `[[openshell.supervisor.middleware]]`; `Describe` response |
| Gateway or middleware rejects its peer before serving health | Missing peer metadata, incompatible protocol major, or unmet `required_capabilities`, such as a version 2-only service that requires `openshell.supervisor-middleware.http-v2` described by a supervisor from 0.1.2 or earlier | Gateway and middleware startup logs; compare `PeerMetadata`; migrating from services built before peer metadata requires a coordinated gateway and middleware outage; serve both HTTP protocols, or recreate sandboxes with older supervisors, before requiring `http-v2` |
| Policy update rejects `network_middlewares` | Unknown middleware name, implementation-owned config invalid, duplicate order, broad/invalid host selector, an `on_uninspectable: deny` (default) selector covering `tls: skip`, `on_error: fail_open` on middleware without WebSocket or legacy HTTP bindings when the entry sets `on_uninspectable: deny`, or, until 0.2.0, `on_error: fail_open` on any middleware that requires `openshell.supervisor-middleware.http-v2`, even with a WebSocket binding (deploy a dual-protocol build to keep WebSocket `fail_open`) | Policy error, gateway logs, middleware `ValidateConfig`, selector, order, `on_error`, and `on_uninspectable` fields |
| `openshell gateway upgrade-check` reports blocking findings | Legacy HTTP services, entries that use them, HTTP `fail_open`, `fail_open` on middleware that requires `http-v2` (`fail_open_on_http_v2_only`), the `on_uninspectable` fallback on `tls: skip` endpoints, unregistered middleware, or policies the gateway cannot resolve | Finding kind (`-o json`) and message; the published 0.2.0 upgrade guide; restart the gateway after upgrading a service so the check sees its new manifest |
| `tls: skip`, h2c, or non-HTTP traffic to a middleware-selected host is blocked, or passes uninspected | The effective `on_uninspectable` of the selecting entries: one `deny` blocks it; all `allow` relay it raw. An omitted value with `on_error: fail_open` is a deprecated `allow` | `FINDING:BLOCKED` or `FINDING:ALLOWED` with `type:openshell.middleware.traffic_uninspectable`; `CONFIG:DEPRECATED ... on_uninspectable fallback` at policy load |
| Sandbox rejects or quarantines a policy that sets `on_uninspectable: allow` for a `tls: skip` host | The sandbox supervisor predates `on_uninspectable`, ignores it, and requires `on_error: fail_open` on that entry | Sandbox policy load status and supervisor version; add `on_error: fail_open` or recreate the sandbox |
| HTTP request returns `middleware_failed` or `middleware_denied`, or WebSocket closes with `1008` | Selected stage failed or explicitly denied admitted traffic | Sandbox OCSF logs; policy-local middleware config; service availability; binding operation and HTTP protocol version; `on_error` for WebSocket and legacy HTTP stages |
| HTTP middleware fails closed despite `on_error: fail_open` | The binding uses HTTP protocol version 2, or the service broke its contract (`UNIMPLEMENTED`, decode failure, unknown result) | `fail_open_not_applied` configuration event; `openshell.middleware.contract_failure` finding; service `Describe` bindings and served gRPC services |
| HTTP request returns `408 Request Timeout`, or `503` with `middleware_failed` | The sandbox stopped sending a body that middleware inspects for 30 seconds, or middleware sessions or legacy work admission are exhausted | `request_client_progress_timeout` event; `openshell.middleware.session_capacity_exhausted` or `openshell.middleware.admission_exhausted` findings; long-lived `STREAM` exchanges holding sessions |
| HTTP response becomes canonical `403 middleware_denied`, `502 response_delivery_failed`, or closes mid-body | Response middleware blocked, failed before commitment, ran out of sessions, or stopped delivery after commitment | Sandbox OCSF response middleware events; `HTTP_RESPONSE/PRE_RETURN` binding and protocol version; offered body modes; `on_error` for legacy stages; `middleware_body_timeout`, `middleware_stall_timeout`, or legacy `whole_body_accumulation_timeout`; service stream lifecycle |
| WebSocket upgrades but a host-matched middleware receives no preflight or message RPC | The implementation did not advertise `WEBSOCKET_MESSAGE/PRE_CREDENTIALS` | `WEBSOCKET_MIDDLEWARE_COVERAGE state=binding_not_selected`; service `Describe`; the upgrade GET may still have used its HTTP binding |
| Binary WebSocket message passes without a middleware RPC | Binary is unsupported by the V1 text-message binding under both `on_error` modes | `WEBSOCKET_MIDDLEWARE_COVERAGE state=unsupported_message_type`; the next text RPC may have a valid sequence gap |
| WebSocket messages stop reaching middleware after one failure | A fail-open stage stream was disabled for the rest of the connection | `openshell.middleware.websocket_stage_disabled`; middleware timeout/stream/protocol logs. A per-message capacity bypass alone leaves the stage active. Reconnect to create a fresh stream after a genuine stream failure |
| Supervisor repeatedly fails to install middleware after enabling gateway JWT signing | Extension credential minting, distribution, or authenticated service connection failed; last-known-good registry remains active | Gateway `RefreshSandboxToken` logs, sandbox configuration events, service token-verification logs, registration TLS/audience settings |

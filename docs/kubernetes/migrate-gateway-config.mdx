# Migrate Helm gateway configuration to `gatewayConfig`

These mappings apply to the main OpenShell gateway chart. The separate
`openshell-workspace` chart keeps its existing values interface.

Chart schema v2 replaces application-specific Helm values with one non-secret
`gatewayConfig` map. Its top-level keys are TOML tables; nested maps are TOML
inline tables. A top-level YAML list is an ordered TOML array of tables, with
one map per `[[table]]` entry. Kubernetes resource references (Secrets, certificates, Services,
and mounts) remain chart values.

## Upgrade compatibility

Existing values files and `--set` overrides continue to work with this version
of the chart without modification. You can upgrade first and migrate individual
settings later. Install and upgrade notes identify deprecated paths; explicitly
supplied component values override their legacy equivalents.

Complete the migration before upgrading to chart `0.2.0`. Replace the release's
stored legacy values with `--reset-values -f migrated-values.yaml` as shown below;
adding new overrides with `--reuse-values` leaves the old keys stored in the
release and does not complete the migration.

The chart accepts the old deployment and application values as deprecated
aliases before chart `0.2.0`. Starting with `0.2.0`, supplying an old path fails
with its replacement instead of silently deploying defaults. When both forms set the same runtime field,
`gatewayConfig` wins. Runtime images and proxy settings may therefore be
migrated incrementally. Kubernetes pull policy spellings such as `Always` are
accepted aliases and normalize to `always`, `if_not_present`, or `never`.
`gatewayConfig` is strictly a non-secret
configuration contract: do not put passwords, tokens, private keys,
`database_url`, or other secret material in it; use Secret-backed environment,
file, or volume configuration instead. Helm serializes unknown fields
generically and cannot determine whether an arbitrary string such as
`api_token` is confidential. It rejects `database_url`, inline URL credentials,
and PEM private keys, but is not a general secret scanner.

Keep Kubernetes resource inputs in their owning component's values. The chart
derives mounted file paths, listener ports, TLS fields, namespaces, and service
account names from those inputs so the resources and runtime configuration agree.

## Component deployment values

The chart groups deployment settings under `gateway`, `supervisor`, and `sandbox`.
`gatewayConfig`, `pkiInitJob`, `grpcRoute`, `certManager`, and `openshiftRoute` stay
at the top level. `gateway.image` and `sandbox.image` keep their existing paths.

| Old path | Replacement |
| --- | --- |
| `replicaCount`, `workload`, `autoscaling` | Corresponding keys under `gateway` |
| `nodeSelector`, `affinity`, `tolerations`, `priorityClassName`, `topologySpreadConstraints` | Corresponding keys under `gateway` |
| `resources`, `probes`, `podLifecycle` | Corresponding keys under `gateway` |
| `podAnnotations`, `podLabels`, `podSecurityContext`, `securityContext` | Corresponding keys under `gateway` |
| `serviceAccount`, `rbac`, `service`, `metrics`, `credentialDrivers` | Corresponding keys under `gateway` |
| `server.extraEnv`, `server.extraVolumes`, `server.extraVolumeMounts` | Corresponding keys under `gateway` |
| `server.dataStorageSize`, `server.dataStorageClass`, `server.externalDbSecret`, `server.dbUrl`, `server.telemetryEnabled` | Corresponding keys under `gateway` |
| `server.disableTls`, `server.tls`, `server.credentialStorage` | Corresponding keys under `gateway` |
| `server.sandboxJwt.signingSecretName`, `server.sandboxJwt.secretDefaultMode` | Corresponding keys under `gateway.sandboxJwt` |
| `server.oidc.caConfigMapName`, `server.providerTokenGrants.spiffe` | Corresponding keys under `gateway` |
| `server.credentialDrivers.kubernetesSecrets.createNamespace`, `server.credentialDrivers.kubernetesSecrets.rbac` | Corresponding keys under `gateway.credentialDrivers.kubernetesSecrets` |
| `server.credentialDrivers.vault.caConfigMapName` | `gateway.credentialDrivers.vault.caConfigMapName` |
| `sandboxServiceAccount`, `sandboxRuntime`, `networkPolicy` | `sandbox.serviceAccount`, `sandbox.runtime`, `sandbox.networkPolicy` |
| `server.sandboxNamespace`, `server.sandboxImagePullSecrets` | `sandbox.namespace`, `sandbox.imagePullSecrets` |

There is no `gateway.server` map. Database URLs remain outside `gatewayConfig`,
which rejects `database_url`. Use `gateway.externalDbSecret` for a PostgreSQL URI.
`gateway.telemetryEnabled` controls the existing environment-only telemetry flag.
Remove `server.ocsfLog.schemaVersion`; it was already ignored. To enable OCSF file
output, set `path` in `gatewayConfig["openshell.gateway.ocsf_log"]`.

During the compatibility window, explicit component settings override legacy
aliases entry by entry. Lists replace whole lists, and explicit empty maps or
lists clear legacy values. `false`, zero, and empty strings retain their meaning.
Null component values inherit legacy overrides or chart defaults; the sparse
defaults in `values.yaml` avoid masking old overrides. Install and upgrade notes
list deprecated paths and the removal version.

Gateway and shared supervisor pods independently support `nodeSelector`,
`affinity`, `tolerations`, `topologySpreadConstraints`, `priorityClassName`,
`schedulerName`, `resources`, pod metadata, security contexts, shutdown grace
periods, and service accounts. CPU utilization autoscaling needs a positive CPU
request; supervisor memory autoscaling uses an absolute memory target. Component
`imagePullSecrets` override chart-wide pull secrets when supplied; an empty list
disables inheritance.

`gateway.serviceAccount`, `supervisor.serviceAccount`, and `sandbox.serviceAccount`
accept `create`, `name`, `labels`, and `annotations`. `create: false` selects an
existing account; an empty name selects `default`. `create: true` generates a name
when omitted. Supervisor accounts receive no gateway RBAC, and token automount
defaults to `false`. Sandbox workloads always disable token automount and use a
scoped projected bootstrap token; setting their automount override to `true` is
rejected. In managed workspace mode, the driver provisions the named sandbox
account in each workspace namespace; provision custom metadata there separately.
With externally managed workspaces, provision the named account in each workspace
namespace. `workspaceResources.enabled=false` disables Helm's sandbox account
creation along with its other workspace resources.

Export stored overrides before upgrading:

```shell
helm get values openshell -n openshell -o yaml > migrated-values.yaml
```

Move the keys in that file using the mappings on this page, retaining unrelated
overrides. Then replace the release's stored values:

```shell
helm upgrade openshell oci://ghcr.io/nvidia/openshell/helm-chart \
  --version <version> -n openshell --reset-values -f migrated-values.yaml
```

`--reuse-values` retains old paths and fails at `0.2.0` even if canonical overrides
are also supplied. Keep a copy of the exported values until the upgrade succeeds.
Equivalent old and new configuration preserves resource names, Service selectors,
and PVC references. Changes to pod specifications or the configuration checksum
can still roll pods during an upgrade.

## Mapping

| Deprecated alias | Schema-v2 location |
| --- | --- |
| `server.name`, `server.logLevel`, `server.enableLoopbackServiceHttp`, `server.policyValidationFailureMode` | `openshell.gateway.{name,log_level,enable_loopback_service_http,policy_validation_failure_mode}` |
| `server.grpcRateLimit.{requests,windowSeconds}` | `openshell.gateway.{grpc_rate_limit_requests,grpc_rate_limit_window_seconds}` |
| `server.otlp.{endpoint,serviceName}` | `openshell.gateway.otlp.{endpoint,service_name}` |
| `server.auth.allowUnauthenticatedUsers` | `openshell.gateway.auth.allow_unauthenticated_users` |
| `server.oidc.*` | `openshell.gateway.oidc` with snake_case keys |
| `server.sandboxImage*`, workspace storage/runtime and user namespace settings | `openshell.drivers.kubernetes`. Kubernetes AppArmor configuration is removed by RFC 0012. |
| `server.drivers.kubernetes.*` | `openshell.drivers.kubernetes` |
| `server.sandboxJwt.{gatewayId,ttlSecs,k8sSaTokenTtlSecs}` | `openshell.gateway.gateway_jwt` or `openshell.drivers.kubernetes.sa_token_ttl_secs` |
| `supervisor.image.*`, `supervisor.sandboxRuntime.*` | `openshell.drivers.kubernetes.{supervisor_image,supervisor_image_pull_policy,sandbox_runtime}`. `supervisor.topology` and `supervisor.sidecar.*` are removed by RFC 0012 with no replacement. |
| `upstreamProxy.*` | `openshell.drivers.kubernetes.{https_proxy,no_proxy,proxy_auth_*,proxy_connect_by_hostname}`. |
| `server.credentialDrivers.{kubernetesSecrets,vault}.*` | `openshell.gateway.credential_drivers` and `openshell.credential_drivers.*` |
| `server.providerTokenGrants.spiffe.{enabled,workloadApiSocketPath}` | `openshell.drivers.kubernetes.provider_spiffe_workload_api_socket_path`; omit it to disable SPIFFE provider grants. |
| `server.hostGatewayIP` | `openshell.drivers.kubernetes.host_gateway_ip`; the chart uses the effective value for pod host aliases too. |

## Examples

The following values configure OIDC, telemetry, sandbox images, managed
workspaces, rate limiting, and the Kubernetes Secrets credential driver before
migration:

```yaml
server:
  oidc:
    issuer: https://idp.example/realms/openshell
    audience: openshell-cli
    jwksTtl: 3600
  otlp:
    endpoint: http://otel-collector:4317
    serviceName: production-gateway
  drivers:
    kubernetes:
      workspaceMode: managed
  grpcRateLimit:
    requests: 120
    windowSeconds: 60
  credentialDrivers:
    kubernetesSecrets:
      enabled: true
      namespace: provider-secrets
sandbox:
  image:
    repository: registry.example/sandbox
    tag: latest
    pullPolicy: IfNotPresent
supervisor:
  image:
    registry: registry.example
    repository: openshell-supervisor
    tag: latest
  sandboxRuntime:
    boundaryPort: 5500
```

After migration, the same settings use `gatewayConfig`:

```yaml
gatewayConfig:
  openshell.gateway.oidc:
    issuer: https://idp.example/realms/openshell
    audience: openshell-cli
    jwks_ttl_secs: 3600
  openshell.gateway.otlp:
    endpoint: http://otel-collector:4317
    service_name: production-gateway
  openshell.drivers.kubernetes:
    default_image: registry.example/sandbox:latest
    image_pull_policy: if_not_present
    supervisor_image: registry.example/openshell-supervisor:latest
    sandbox_runtime:
      boundary_port: 5500
    workspace_mode: managed
  openshell.gateway:
    grpc_rate_limit_requests: 120
    grpc_rate_limit_window_seconds: 60
    credential_drivers: [kubernetes-secrets]
  openshell.credential_drivers.kubernetes-secrets:
    namespace: provider-secrets
```

For Vault, set `openshell.gateway.credential_drivers: [vault]` and configure
`openshell.credential_drivers.vault`; use `credentialDrivers.vault.caConfigMapName`
for a private Vault CA. For a proxy, use the Kubernetes-driver fields in
`gatewayConfig`. TLS remains Secret-backed; set `server.disableTls: true` only for
trusted external termination. A null map field omits it; null array elements
are invalid. Strings are serialized literally; Helm template expressions inside
them are not evaluated.

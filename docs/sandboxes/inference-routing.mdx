OpenShell gives agents access to inference APIs through provider attachments. The
provider profile contributes the upstream network policy, allowed binaries, and
credential bindings. The provider record supplies credentials and configuration.

OpenShell does not proxy model requests through a gateway-managed inference
route. Agents use each provider's native endpoint and SDK.

## Configure a Built-in Provider

Create a provider from credentials already present in your shell:

```shell
openshell provider create --name openai-prod --type openai --from-existing
```

Attach it when you create a sandbox:

```shell
openshell sandbox create --provider openai-prod
```

You can also attach it to an existing sandbox:

```shell
openshell provider attach openai-prod --sandbox my-sandbox
```

The OpenAI profile allows the native `api.openai.com` endpoint and binds
`OPENAI_API_KEY` to that endpoint. The credential is resolved at the network
boundary rather than exposed as plaintext to the agent process. Other built-in
inference profiles work the same way:

```shell
openshell provider create --name anthropic-prod --type anthropic --from-existing
openshell sandbox create --provider anthropic-prod
```

The application selects its model and request timeout through its native SDK or
command-line options. OpenShell does not rewrite the model field.

## Configure a Custom or Self-hosted Endpoint

A base URL override does not change a built-in profile's network policy. Import a
custom profile when the agent must connect to an alternate inference host. This
keeps the credential binding and destination policy reviewable together.

For example, save this profile as `ollama-profile.yaml`:

```yaml
id: ollama-openai
display_name: Ollama OpenAI API
description: OpenAI-compatible Ollama endpoint on the gateway host
category: inference
inference_capable: true
credentials:
  - name: api_key
    env_vars: [OPENAI_API_KEY]
    required: true
    auth_style: bearer
    header_name: authorization
endpoints:
  - host: host.openshell.internal
    port: 11434
    protocol: rest
    access: read-write
    enforcement: enforce
binaries:
  - /usr/bin/curl
  - /usr/local/bin/curl
```

Import the profile, create a provider, and attach it:

```shell
openshell provider profile import -f ollama-profile.yaml
openshell provider create \
    --name ollama \
    --type ollama-openai \
    --credential OPENAI_API_KEY=unused \
    --config OPENAI_BASE_URL=http://host.openshell.internal:11434/v1
openshell sandbox create --provider ollama
```

Add the agent or client binary paths it needs to the custom profile. See
[Provider Profiles](/providers/profiles) for the complete schema and update
workflow.

## Migration from Managed Inference Routes

Managed inference routes and `https://inference.local` have been removed.

- `openshell inference set|get|update|delete` no longer exists.
- Gateway upgrades delete stored inference-route records.
- Sandboxes must call the provider's native endpoint.
- Attach the provider to each sandbox that needs it.
- Import an endpoint-bearing custom profile for a private, local, or
  OpenAI-compatible alternate endpoint.
- Select the model and timeout in the application instead of gateway route
  configuration.
- Restart or recreate sandboxes that were running before the upgrade so no
  process retains stale `inference.local` assumptions.

There is no automatic route-to-provider migration because a managed route did
not record the sandbox attachments, binaries, and endpoint policy required for
safe native access.

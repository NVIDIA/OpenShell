A sandbox policy can be written in [Cedar](https://www.cedarpolicy.com/) instead of YAML. Cedar then decides every network connection, every inspected HTTP or JSON-RPC request, and the filesystem paths Landlock allows. A sandbox uses one format for its whole lifetime: YAML policies are evaluated by the built-in Rego engine, and Cedar policies by Cedar.

Cedar's restricted language makes policies easier to analyze, for example to check that a revision grants no more access than the one it replaces. OpenShell accepts only Cedar policy shapes it can enforce exactly as written, and rejects the rest when you submit the policy.

## Apply a Cedar Policy

OpenShell treats a policy file as Cedar when its extension is `.cedar`, in any case. Any other extension is parsed as YAML.

Create a sandbox with a Cedar policy:

```shell
openshell sandbox create --policy ./policy.cedar -- claude
```

Replace the policy on a running sandbox:

```shell
openshell policy set <name> --policy ./policy.cedar --wait
```

The CLI validates the file before sending it, and the gateway validates it again. If the sandbox cannot load a revision, the `policy_validation_failure_mode` setting applies as it does for YAML policies. Refer to [Manage Policies](/how-it-works/policies/manage-policies).

`openshell policy get <name>` prints the Cedar text of a Cedar sandbox's policy.

## Add Middleware

Middleware is configuration, not access control, so it is supplied separately from the Cedar file. Write a middleware file that contains only a `network_middlewares` section, in the same format as the section of a YAML policy:

```yaml
network_middlewares:
  regex-redactor:
    name: Redact API tokens
    middleware: openshell/regex
    order: 10
    config:
      mode: redact
    on_error: fail_closed
    endpoints:
      include: ["api.github.com"]
```

Pass it with `--middleware` when you create the sandbox or set its policy:

```shell
openshell sandbox create --policy ./policy.cedar --middleware ./middleware.yaml -- claude
openshell policy set <name> --policy ./policy.cedar --middleware ./middleware.yaml --wait
```

`openshell policy get <name>` prints the middleware as a separate section after the Cedar text. The Landlock compatibility mode and process identity of a Cedar sandbox use their defaults.

## Policy Model

Every policy is evaluated against a fixed schema in the `Sandbox` namespace. The principal is always a `Sandbox::Process`.

| Action | Resource | Context fields | Decides |
|---|---|---|---|
| `ReadFile`, `WriteFile` | `FilesystemPath` | none | Landlock grants, fixed at sandbox start. |
| `NetworkConnect` | `NetworkEndpoint` | `binary_path`, `ancestors` | Whether a process may open a connection. |
| `HttpRequest` | `NetworkEndpoint` | `binary_path`, `ancestors`, `method`, `path`, and the protocol fields below | Each request on an inspected connection. |

A `NetworkEndpoint` id is `"host:port"`, with a lowercase host. `NetworkConnect` also declares `method`, `path`, and `command`, but they are always empty because no request has been read at connect time. Put method and path conditions on `HttpRequest`.

This example grants filesystem access, allows `curl` to connect to the GitHub API, and inspects each request on that connection:

```cedar
permit (
    principal is Sandbox::Process,
    action in [Sandbox::Action::"ReadFile", Sandbox::Action::"WriteFile"],
    resource is Sandbox::FilesystemPath
)
when { resource in Sandbox::FilesystemPath::"/sandbox" || resource in Sandbox::FilesystemPath::"/tmp" };

permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"ReadFile",
    resource in Sandbox::FilesystemPath::"/usr"
);

permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"NetworkConnect",
    resource == Sandbox::NetworkEndpoint::"api.github.com:443"
)
when { context.binary_path == "/usr/bin/curl" };

permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"HttpRequest",
    resource == Sandbox::NetworkEndpoint::"api.github.com:443"
)
when { context.method == "GET" && context.path like("/repos/*/*", "/") };
```

## Filesystem Rules

Landlock applies a flat allow-list of path subtrees when the sandbox starts, so OpenShell accepts only filesystem policies that mean exactly that. A policy that can apply to `ReadFile` or `WriteFile` must:

- Be a `permit`. A `forbid` that can apply to files is rejected.
- List only `ReadFile` and `WriteFile` in its action scope.
- Use `principal` or `principal is Sandbox::Process`.
- Name paths with `resource in Sandbox::FilesystemPath::"/path"`, either in the scope or in a single `when` clause that only joins such tests with `||`.

`resource ==` is rejected because Landlock grants the whole subtree under a directory. Paths must be absolute, must not contain `..`, and `/` cannot be granted write access. A policy that lists `WriteFile` grants read-write access to its paths.

The supervisor adds the same baseline runtime paths it adds for YAML policies. On a running sandbox, a policy update can add filesystem paths but cannot remove them, because Landlock cannot revoke access from a running process.

## Network Rules

Cedar evaluates `NetworkConnect` for every outbound connection, with the calling binary in `context.binary_path` and its ancestors in `context.ancestors`. Conditions on these actions are evaluated by Cedar as written.

<Warning>
Cedar compares binary paths exactly. Use the resolved executable path, such as `/usr/bin/python3.12`, rather than a symlink such as `/usr/bin/python3`, or a glob such as `context.binary_path like("/usr/lib/postgresql/*/bin/psql", "/")`.
</Warning>

## Globs

Write globs with a delimiter, as `like("pattern", "delimiter")`. With a delimiter, `*` matches within one segment and `**` matches across segments, as in YAML policies. Use `"."` for hosts and `"/"` for paths. Without a delimiter, `like` treats every `*` as matching across segments, so `context.path like "/repos/*"` also matches `/repos/a/b/c`.

```cedar
permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"NetworkConnect",
    resource is Sandbox::NetworkEndpoint
)
when {
    resource.host like("*.example.com", ".")
    && resource.port == 443
    && context.binary_path == "/usr/bin/curl"
};
```

## Policy DNS

Policy DNS resolves a host when a `NetworkConnect` permit names it in its scope, such as `resource == Sandbox::NetworkEndpoint::"pypi.org:443"`, or requires both the host and the port in its `when` conditions, as in the example above. The host condition can be an exact string or a host glob with a `.` delimiter that follows the YAML wildcard host rules: `*` or `**` as the whole first label, `*` within the first label, `*` as a whole later label, and no wildcard top-level domain such as `*.com`. Policy DNS does not resolve any other host, so the connection fails closed.

A host named exactly may resolve to a private address. A host matched by a glob may not, unless you name it exactly in another permit.

## Request Rules

The proxy decides at connect time whether to inspect a connection request by request. It inspects every endpoint that an `HttpRequest` policy names in its scope, whether the policy is a `permit` or a `forbid`. An `HttpRequest` policy without an endpoint in its scope is rejected, because the proxy could not tell which connections it applies to.

Cedar denies by default. Once any `HttpRequest` policy names an endpoint, each request to that endpoint needs a matching `permit`.

Endpoints are parsed as REST by default. Add `@protocol("json-rpc")`, `@protocol("mcp")`, or `@protocol("graphql")` to an `HttpRequest` policy to inspect that protocol instead. All policies that declare a protocol for one endpoint must agree. `@protocol("sql")` is rejected, because OpenShell does not inspect SQL traffic.

Fields that do not apply to a request are empty strings, `false`, or empty sets.

| Protocol | Context fields |
|---|---|
| REST | `method`, `path` |
| JSON-RPC | `jsonrpc_method`, `jsonrpc_response` |
| MCP | `jsonrpc_method`, `mcp_tool`, `mcp_method_class`, `jsonrpc_receive_stream`, `jsonrpc_response` |
| GraphQL | `graphql_operation_type`, `graphql_operation_name`, `graphql_fields` |

`context.method` is always uppercase. Unlike YAML, a `GET` condition does not also allow `HEAD`, so list `HEAD` when you want it allowed.

For JSON-RPC and MCP, each call is evaluated on its own, and `method` is empty for a call. OpenShell denies a request that fails JSON-RPC inspection, and a call or response frame that is not sent with `POST`, before evaluating it.

### MCP

`mcp_tool` is the tool name of a `tools/call` request. `mcp_method_class` is `available` for a core method of the selected MCP revision, and `extension` for any other method. An MCP endpoint does not allow its receive stream or client response frames by itself, so permit them explicitly. The revision is the YAML default, `2025-11-25`.

```cedar
@protocol("mcp")
permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"HttpRequest",
    resource == Sandbox::NetworkEndpoint::"mcp.example.com:443"
)
when {
    context.path == "/mcp"
    && context.mcp_method_class == "available"
    && (["initialize", "tools/list"].contains(context.jsonrpc_method)
        || (context.jsonrpc_method == "tools/call" && context.mcp_tool like("github.*", ".")))
};

permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"HttpRequest",
    resource == Sandbox::NetworkEndpoint::"mcp.example.com:443"
)
when {
    context.path == "/mcp"
    && ((context.method == "GET" && context.jsonrpc_receive_stream) || context.jsonrpc_response)
};
```

### GraphQL

OpenShell evaluates each operation in a request separately and denies the request if any operation is denied. `graphql_operation_type` is lowercase, and empty for a hash-only persisted query, which no YAML-style registry can allow on a Cedar sandbox. Match exact field names with `containsAll` and `containsAny`:

```cedar
@protocol("graphql")
permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"HttpRequest",
    resource == Sandbox::NetworkEndpoint::"api.github.com:443"
)
when {
    context.path == "/graphql"
    && (context.graphql_operation_type == "query"
        || (context.graphql_operation_type == "mutation"
            && context.graphql_fields.containsAny(["createIssue", "commentOnIssue"])
            && ["createIssue", "commentOnIssue"].containsAll(context.graphql_fields)))
};
```

Field globs, such as YAML `fields: ["create*"]`, cannot be written, because they need every field to match a pattern. Operation name globs work with `like`.

## Audit Mode

Add `@enforcement("audit")` to an `HttpRequest` policy to make it audit-only. The policy's action scope must be exactly `HttpRequest`.

When every `HttpRequest` policy for an endpoint is audit-only, the endpoint runs in audit mode, like a YAML endpoint with `enforcement: audit`. OpenShell evaluates each request against those policies, logs a request they deny with decision `audit`, and forwards it.

On an endpoint that has other `HttpRequest` policies, audit-only policies are staged. They never change a decision. OpenShell logs each request whose decision they would change, with `cedar_audit:staged_deny` or `cedar_audit:staged_allow` and the policies that would decide it. Use a staged `forbid` to see what a new restriction would block before you enforce it:

```cedar
@enforcement("audit")
@id("no-webhook-changes")
forbid (
    principal is Sandbox::Process,
    action == Sandbox::Action::"HttpRequest",
    resource == Sandbox::NetworkEndpoint::"api.github.com:443"
)
when { context.path like("/repos/*/*/hooks/**", "/") };
```

Logs name policies by their `@id` annotation when they have one.

## Providers and Credentials

Providers attached to a Cedar sandbox supply credentials but never grant access. The Cedar policy alone decides which endpoints a process can reach. Attaching a provider makes its credentials available on connections that Cedar already allows to the provider's endpoints, with the provider's credential settings, such as request signing and body rewriting.

A provider endpoint that carries credentials must be inspected per request, so write an `HttpRequest` policy for it. OpenShell refuses connections to a credentialed endpoint that Cedar does not inspect, unless the provider allows uninspected credentials.

`openshell policy get <name> --full` shows the provider rules delivered to the sandbox in a separate section after the Cedar text and middleware, with a list of the endpoints that carry credentials. `--base` omits them.

```cedar
permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"NetworkConnect",
    resource == Sandbox::NetworkEndpoint::"api.github.com:443"
)
when { context.binary_path == "/usr/bin/gh" };

permit (
    principal is Sandbox::Process,
    action == Sandbox::Action::"HttpRequest",
    resource == Sandbox::NetworkEndpoint::"api.github.com:443"
)
when { context.method == "GET" };
```

## Limitations

- A sandbox cannot switch between YAML and Cedar after creation. Recreate the sandbox to change formats.
- Global policies must be YAML.
- Incremental `openshell policy update` merges are not available for Cedar policies. Use `openshell policy set` with the full policy.
- Policy templates are not supported.
- Query parameter matching, WebSocket message rules, and GraphQL persisted-query registries are not available.

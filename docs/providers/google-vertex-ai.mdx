Google Vertex AI hosts Gemini, Anthropic Claude, and third-party models. The
`google-vertex-ai` provider profile grants native Vertex API access and binds a
short-lived Google Cloud token to the supported Vertex endpoints.

OpenShell does not translate request protocols or construct model paths. The
sandboxed client calls the Vertex REST API directly.

## Prerequisites

- A GCP project with the Vertex AI API enabled.
- A service account with the Vertex AI User role, or `gcloud` Application
  Default Credentials for local development.

## Create a Provider

### Service Account

Create the provider with the service account key as non-injectable refresh
bootstrap material:

```shell
openshell provider create \
  --name vertex-prod \
  --type google-vertex-ai \
  --credential GOOGLE_SERVICE_ACCOUNT_KEY="$(cat /path/to/key.json)" \
  --config VERTEX_AI_PROJECT_ID=my-gcp-project \
  --config VERTEX_AI_REGION=us-central1
```

Configure gateway-managed access-token refresh:

```shell
openshell provider refresh configure vertex-prod \
  --credential-key GOOGLE_VERTEX_AI_SERVICE_ACCOUNT_TOKEN \
  --strategy google-service-account-jwt \
  --material client_email="sa@my-gcp-project.iam.gserviceaccount.com" \
  --secret-material-env private_key=VERTEX_SERVICE_ACCOUNT_PRIVATE_KEY
```

Set `VERTEX_SERVICE_ACCOUNT_PRIVATE_KEY` in the CLI environment before running
the command. The private key remains gateway-side; the gateway rotates the
short-lived access token used at the network boundary.

### gcloud Application Default Credentials

For local development:

```shell
gcloud auth application-default login

openshell provider create \
  --name vertex-local \
  --type google-vertex-ai \
  --from-gcloud-adc \
  --config VERTEX_AI_PROJECT_ID=my-gcp-project \
  --config VERTEX_AI_REGION=us-central1
```

`--from-gcloud-adc` configures the gateway refresh flow and mints the initial
access token before returning.

## Attach the Provider

Attach the provider when creating a sandbox:

```shell
openshell sandbox create --provider vertex-prod
```

Or attach it to an existing sandbox:

```shell
openshell provider attach vertex-prod --sandbox my-sandbox
```

The built-in profile permits these native Vertex endpoint shapes:

- `*-aiplatform.googleapis.com`
- `aiplatform.googleapis.com`
- `aiplatform.us.rep.googleapis.com`
- `aiplatform.eu.rep.googleapis.com`

It also projects the configured project and region aliases used by supported
clients. The application remains responsible for choosing the publisher, model,
request path, request body, and timeout.

## Configuration Keys

| Key | Required | Description |
|---|---|---|
| `VERTEX_AI_PROJECT_ID` | Yes | GCP project ID projected to the sandbox's supported Google Cloud and Vertex aliases. |
| `VERTEX_AI_REGION` | No | Vertex location. Defaults are client-specific; set it explicitly for predictable paths. |
| `GOOGLE_VERTEX_AI_BASE_URL` | No | Client configuration only. It does not add an endpoint to policy. |
| `VERTEX_AI_BASE_URL` | No | Alias for `GOOGLE_VERTEX_AI_BASE_URL`. |
| `VERTEX_AI_PUBLISHER` | No | Client configuration for tools that consume it. OpenShell does not use it to rewrite requests. |

For a private service, proxy, or endpoint outside the built-in host patterns,
import a custom provider profile containing that endpoint.

## Call Vertex Directly

Use the native Vertex REST URL for the selected model. For example, clients can
send the provider token placeholder in an Authorization header; OpenShell
resolves it only for an endpoint authorized by the attached profile:

```shell
curl \
  -H "Authorization: Bearer $GOOGLE_VERTEX_AI_SERVICE_ACCOUNT_TOKEN" \
  -H "Content-Type: application/json" \
  "https://us-central1-aiplatform.googleapis.com/v1/projects/$VERTEX_AI_PROJECT_ID/locations/$VERTEX_AI_REGION/publishers/google/models/MODEL:generateContent" \
  --json '{"contents":[{"role":"user","parts":[{"text":"Hello"}]}]}'
```

ADC-backed providers use `GOOGLE_VERTEX_AI_TOKEN` instead. Consult the Google
Cloud model documentation for the exact publisher, model, region, and request
schema.

## Migration from `inference.local`

Remove any `ANTHROPIC_BASE_URL=https://inference.local` or equivalent local
route setting. Attach the Vertex provider to the sandbox and configure the
client for Vertex's native API. OpenShell no longer rewrites OpenAI or Anthropic
requests into Vertex requests.

Use the Python SDK to manage sandboxes from applications, notebooks, and
automation. It can reuse gateway registration and authentication state created
by the OpenShell CLI. Use the SDK and gateway from the same OpenShell release
when possible.

## Install the SDK

The package requires Python 3.11 or later. Add it to your project with `uv`:

```shell
uv add openshell
```

The `openshell` package contains the SDK. It does not install the OpenShell CLI.

## Connect to a Registered Gateway

Register and select a gateway with the CLI first. Then construct the client from
the active gateway:

```python
from openshell import SandboxClient

with SandboxClient.from_active_cluster() as client:
    health = client.health()
    print(health.version)
```

`from_active_cluster()` reads the selected gateway endpoint, TLS files, and
OIDC token state. It refreshes an expiring OIDC token by default and writes the
rotated bundle back for other OpenShell processes.

For a direct local plaintext connection, pass a `host:port` endpoint:

```python
from openshell import SandboxClient

with SandboxClient("127.0.0.1:8080") as client:
    print(client.health().version)
```

For service automation against an OIDC gateway, use
`ClientCredentialsAuth`. Non-loopback endpoints require TLS:

```python
import os

from openshell import ClientCredentialsAuth, SandboxClient

auth = ClientCredentialsAuth(
    issuer="https://idp.example.com/realms/openshell",
    client_id="openshell-service",
    client_secret=lambda: os.environ["OPENSHELL_OIDC_CLIENT_SECRET"],
    audience="openshell-gateway",
)

with SandboxClient.from_active_cluster(client_credentials=auth) as client:
    print(client.health().version)
```

## Retrieve Provider Credentials

Connect directly with a trusted `OU=operator` client certificate after enabling
[operator authentication](/how-it-works/gateways/authentication#mtls-operators).
Do not supply a bearer token or use an OIDC login for this connection. No sandbox
creation or provider attachment is required.

```python
from datetime import timedelta
from pathlib import Path

from openshell import SandboxClient, TlsConfig

tls = TlsConfig(
    ca_path=Path("ca.crt"),
    cert_path=Path("operator.crt"),
    key_path=Path("operator.key"),
)
with SandboxClient("gateway.example.com:443", tls=tls) as client:
    credentials = client.providers().get_credentials(
        "my-graph",
        ["MS_GRAPH_ACCESS_TOKEN"],
        workspace="production",
        minimum_remaining_lifetime=timedelta(minutes=5),
    )
    token = credentials["MS_GRAPH_ACCESS_TOKEN"].value
```

`ProviderClient` also accepts an existing `grpc.Channel`. Its
`get_credentials()` method requires an explicit workspace and key selection.
It returns a dictionary of `ProviderCredentialValue` objects with `value` and
optional `expiration_time`, a UTC `datetime`. Pass a `timedelta` for
`minimum_remaining_lifetime`; omission or zero uses the gateway default.
The helper uses the connection's timeout and does not retry or cache exports.
Gateway failures raise `GatewayError`; invalid local selections raise `ValueError`.

The value is excluded from the object's `repr`, but serialization still exposes
it. Keep exported secrets out of logs and shared output. See
[Retrieve Runtime Credentials](/how-it-works/providers/overview#retrieve-runtime-credentials)
for freshness, supported credentials, and the export security boundary.

## Create and Use a Sandbox

Python SDK methods take an explicit workspace. This example creates a sandbox,
waits for readiness, runs a command, and waits for deletion:

```python
from openshell import SandboxClient

with SandboxClient.from_active_cluster() as client:
    sandbox = client.create(
        workspace="default",
        name="sdk-example",
    )
    client.wait_ready(
        sandbox.name,
        workspace="default",
        timeout_seconds=120,
    )

    result = client.exec(
        sandbox.name,
        ["python", "-c", "print('hello from OpenShell')"],
        workspace="default",
    )
    print(result.stdout, end="")

    deletion = client.delete(sandbox.name, workspace="default")
    client.wait_deleted(
        sandbox.name,
        workspace="default",
        expected_sandbox_id=deletion.sandbox_id,
    )
```

Use `create_session()` when you want an object that retains the sandbox name and
workspace for repeated exec, stop, start, and delete operations. List methods
return lazy `Pager` instances; use `list_all()` only when you want to fetch the
complete collection.

## Use the Async Client

`AsyncSandboxClient` provides the same sandbox operations and arguments as
`SandboxClient` over `grpc.aio`. Construct and use it on one event loop:

```python
from openshell import AsyncSandboxClient

async def run():
    async with AsyncSandboxClient.from_active_cluster() as client:
        sandbox = await client.get("worker", workspace="default")
        result = await client.exec(sandbox.name, ["echo", "hello"], workspace="default")
        print(result.stdout)

        async for page in client.list(workspace="default"):
            for item in page.items:
                print(item.name)
```

List methods return lazy `AsyncPager` objects without an `await`. Use
`await client.list_all(...)` to collect every page. The provider, sandbox-template,
and workspace clients also have `Async` counterparts. Authentication settings
match the synchronous client; credential refresh runs off the event loop.

Both sandbox clients accept a caller-configured channel through `from_channel()`.
That factory borrows the channel: closing the client leaves it open. Clients
constructed from an endpoint or registered gateway own and close their channels.

RPC methods accept `timeout` in seconds to override the client default. This is
separate from an exec command's `timeout_seconds`. Mutations that support gateway
deduplication accept `request_id`; reuse the same ID and payload when explicitly
retrying an uncertain result. Request IDs do not enable general automatic retries. Exec retains the gateway
owner-route fallback when the route fails before the first response; it never
replays a command after receiving output.

Async task cancellation propagates to the active RPC. For early exit from
`exec_stream()`, use `contextlib.aclosing()` so the stream is cancelled promptly.
Gateway RPC failures raise `GatewayError`, preserving the gRPC status and details.

## Manage Services and Read Logs

Both sandbox clients expose service creation, lookup, pagination, and deletion.
Use `get_logs()` for structured gateway and supervisor logs:

```python
from openshell import SandboxClient

with SandboxClient.from_active_cluster() as client:
    session = client.get_session("worker", workspace="default")
    endpoint = session.expose_service(name="api", target_port=8000)
    print(endpoint.url)
    for page in session.list_services():
        for service in page.items:
            print(service.endpoint.name, service.url)
    logs = session.get_logs(lines=100, sources=["sandbox"])
    for entry in logs.logs:
        print(entry.message, dict(entry.fields))
    session.delete_service(name="api", allow_missing=True)
```

`get_logs()` preserves `buffer_total`, the unfiltered count of buffered entries.
Its optional `since` argument takes a timezone-aware `datetime`. These logs do
not include arbitrary workload output written to files; use exec to read those
files. Service and log results retain their complete generated protobuf fields.

Import supported protobuf-backed inputs and results from `openshell.types`,
including `SandboxSpec`, `SandboxTemplate`, `SandboxPolicy`, `SandboxPhase`,
`ServiceEndpointResponse`, and `GetSandboxLogsResponse`.

## Observe a Sandbox

`watch()` streams status snapshots and optionally logs and platform events. It
returns complete `SandboxStreamEvent` messages, including warnings and draft
policy notifications. Use `contextlib.closing()` for sync iteration or
`contextlib.aclosing()` for async iteration to cancel promptly on early exit:

```python
from contextlib import aclosing

async def observe(client):
    async with aclosing(client.watch("worker", workspace="default", follow_logs=True)) as events:
        async for event in events:
            kind = event.WhichOneof("payload")
            if kind == "log":
                print(event.log.message)
            elif kind == "warning":
                print(event.warning.message)
```

Watch streams have no deadline unless `timeout` is supplied. To resume logs and
platform events, retain the greatest nonempty cursor you have processed on that
stream and pass it as `resume_after_cursor`. Status and warning messages may
have no cursor. The SDK does not reconnect or reset cursors automatically;
`OUT_OF_RANGE` means the cursor is no longer usable and requires an explicit
decision to start a new watch. Preserve warnings as evidence of event gaps.

Use `wait_completed()` for a job running as the sandbox's canonical main process.
It returns the completed `SandboxRef`, raises on error, stopping, or deletion,
and detects a same-name replacement. Supply `expected_sandbox_id=sandbox.id`
from creation to pin the target before the first poll. Its `timeout_seconds`
bounds polling RPCs and sleeps; `poll_interval` controls the polling frequency.
Use `exec()` to wait for a separately executed command instead.

## Manage Provider Attachments and Configuration

Use `attach_provider()`, `detach_provider()`, and `list_providers()` on either
sandbox client or a bound session. Attachment mutations return the complete
response, including the updated sandbox and a receipt. Persisting an attachment
does not mean its credentials are installed:

```python
with SandboxClient.from_active_cluster() as client:
    sandbox = client.get("worker", workspace="default")
    result = client.attach_provider(
        sandbox.name,
        "github",
        workspace="default",
        expected_resource_version=sandbox.resource_version,
    )
    status = client.get_provider_status(
        sandbox.name,
        "github",
        workspace="default",
        receipt_id=result.receipt.receipt_id,
    )
    print(status.state)
```

Use `get_config()` to inspect effective configuration and admission state.
`set_policy()` and `set_setting()` return the submitted revision details;
`get_policy_status(version=...)` and `list_policies()` expose application status
and history. A successful update RPC does not establish that the policy is loaded.
Sandbox policy changes may alter network policies only; static fields must match
the create-time policy. These helpers always use sandbox scope.

Mutation helpers accept `expected_resource_version` where the protocol supports
it. Read it from `SandboxRef.resource_version`; a conflicting change raises
`GatewayError` with `ABORTED`. The SDK never retries a conflict automatically.
`SandboxRef.annotations` exposes the gateway's current annotations.

## Call Generated RPCs

The generated gRPC stubs include concrete request and response types for synchronous `grpc.Channel` and asynchronous `grpc.aio.Channel` connections. Install the dependency type stubs in your development environment for editor signatures and type checking:

```shell
uv add --dev types-grpcio 'types-protobuf>=6.32,<7'
```

Construct `OpenShellStub` with your channel. The channel determines whether calls return responses directly or awaitable gRPC calls:

```python
import grpc.aio

from openshell._proto import datamodel_pb2 as dm
from openshell._proto import openshell_pb2 as pb
from openshell._proto.openshell_pb2_grpc import OpenShellStub


async def get_provider(channel: grpc.aio.Channel, name: str) -> pb.ProviderResponse:
    stub = OpenShellStub(channel)
    return await stub.GetProvider(
        pb.GetProviderRequest(
            workspace_scope=dm.WorkspaceSelector(workspace="default"),
            name=name,
        ),
        timeout=30,
    )
```

Your application configures the channel's TLS and authentication, supplies RPC deadlines, and closes the channel. Create and use async channels on the same event loop. Cancellation and gRPC errors propagate directly. Generated stubs do not reuse SDK client authentication automatically. Use `AsyncSandboxClient` for the higher-level async methods and managed authentication.

If you annotate a stored async stub explicitly, use a deferred annotation such as `"openshell_pb2_grpc.OpenShellAsyncStub"`. That type exists only in the `.pyi` file; construct `OpenShellStub` at runtime. The same convention applies to credential-driver stubs.

## Implement a Credential Driver

The SDK includes generated message classes, type stubs, and gRPC bindings for
the credential-driver and extension protocols:

```python
from openshell._proto import credential_driver_pb2, credential_driver_pb2_grpc
from openshell._proto import datamodel_pb2, extension_pb2
```

Subclass `credential_driver_pb2_grpc.CredentialDriverServicer` and register your
implementation with `add_CredentialDriverServicer_to_server()` from the same
module. Clients use `CredentialDriverStub`. The generated messages share
`datamodel_pb2.CredentialHandle` and `extension_pb2.PeerMetadata` with the SDK.
Use bindings from the same OpenShell release as your gateway; these modules
expose the internal credential-driver contract.

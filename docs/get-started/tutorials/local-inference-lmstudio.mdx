This tutorial gives a sandbox native access to an LM Studio server running on
the gateway host.

## Start LM Studio

Enable the OpenAI-compatible server and configure it to listen on
`0.0.0.0:1234`. In headless mode:

```shell
lms daemon up
lms server start --bind 0.0.0.0
lms get qwen/qwen3.5-2b
lms load qwen/qwen3.5-2b
```

## Import a Provider Profile

Save this as `lmstudio-profile.yaml`:

```yaml
id: lmstudio-openai
display_name: LM Studio OpenAI API
description: Local OpenAI-compatible LM Studio server
category: inference
inference_capable: true
credentials:
  - name: api_key
    env_vars: [OPENAI_API_KEY]
    required: true
    auth_style: bearer
    header_name: authorization
endpoints:
  - host: host.openshell.internal
    port: 1234
    protocol: rest
    access: read-write
    enforcement: enforce
binaries:
  - /usr/bin/curl
  - /usr/local/bin/curl
```

Import it and create the provider:

```shell
openshell provider profile import -f lmstudio-profile.yaml
openshell provider create \
  --name lmstudio \
  --type lmstudio-openai \
  --credential OPENAI_API_KEY=lmstudio \
  --config OPENAI_BASE_URL=http://host.openshell.internal:1234/v1
```

## Verify from a Sandbox

Attach the provider and call LM Studio's native endpoint:

```shell
openshell sandbox create --provider lmstudio -- \
  sh -lc 'curl http://host.openshell.internal:1234/v1/chat/completions \
    -H "Authorization: Bearer $OPENAI_API_KEY" \
    -H "Content-Type: application/json" \
    --data "{\\"model\\":\\"qwen/qwen3.5-2b\\",\\"messages\\":[{\\"role\\":\\"user\\",\\"content\\":\\"hello\\"}]}"'
```

Add other client binary paths to the profile before using their SDKs or CLIs.
The client selects the model and timeout; OpenShell does not rewrite either.

OpenShell can run any agent that is available in a sandbox image. Configure the
agent's external services, choose its image and policy, then create the sandbox
with the agent as its main process.

**1. Configure what the agent has access to.**

A [provider profile](/providers/profiles) defines the credentials, service
endpoints, and executable paths an agent may use. Import a reviewed profile,
then [create a provider](/sandboxes/manage-providers#create-a-provider) that
stores the credentials for one deployment of that service.

```shell
openshell provider profile lint -f agent-provider.yaml
openshell provider profile import -f agent-provider.yaml

AGENT_API_KEY=your-key \
  openshell provider create \
    --name model-provider \
    --type agent-provider \
    --from-existing
```

The environment variable must match a credential declared in the profile.
OpenShell stores the real value in its credential store. The sandbox receives a
placeholder that the supervisor resolves only for approved requests to the
profile's endpoints.

**2. Configure the sandbox image.**

Build or select a [sandbox image](/sandboxes/manage-sandboxes#sandbox-images)
containing the agent and every tool it needs:

```shell
docker build -t agent:local .
```

For a remote gateway, push the image to a registry that the gateway can pull
from. Use an explicit version instead of a mutable tag for reproducible
deployments.

The built-in fallback policy grants access to the working directory and common
runtime paths, and denies network egress unless an attached provider contributes
an endpoint. Create a custom [sandbox policy](/sandboxes/policies) when the
agent needs more filesystem access, package registries, source hosts, tool
servers, or other destinations.

**3. Create the sandbox.**

[Create the sandbox](/sandboxes/manage-sandboxes#create-a-sandbox), attach the
provider, and pass the agent command after `--`:

```shell
openshell sandbox create \
  --name my-agent \
  --from agent:local \
  --provider model-provider \
  -- agent
```

Add `--policy sandbox-policy.yaml` when the workload needs a custom policy. The
command after `--` becomes the sandbox's main process, and every child process
it starts remains inside the sandbox boundary.

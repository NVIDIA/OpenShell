OpenShell can run any agent that is available in a sandbox image. Configure the
agent's external services, choose its image and policy, then create the sandbox
with the agent as its main process.

**1. Configure what the agent has access to.**

A [provider profile](/how-it-works/providers/profiles) defines the credentials, service
endpoints, and executable paths an agent may use. This example runs OpenCode
against Anthropic. Download the
[example Anthropic profile](https://github.com/NVIDIA/OpenShell/blob/main/providers/anthropic.yaml),
set its `binaries` to the OpenCode executable in the image, then import it and
[create a provider](/how-it-works/providers/overview#create-a-provider) that
stores its credentials.

```shell
curl -fsSLo anthropic.yaml \
  https://raw.githubusercontent.com/NVIDIA/OpenShell/main/providers/anthropic.yaml
sed -i.bak 's|^binaries: .*|binaries: [/usr/local/bin/opencode]|' anthropic.yaml

openshell profile import -f anthropic.yaml

openshell provider create \
  --name anthropic \
  --type anthropic \
  --from-existing
```

Set `ANTHROPIC_API_KEY` before creating the provider. OpenShell stores its
value in the credential store. Only the listed executable can send the key, and
only to `api.anthropic.com`.

**2. Choose the sandbox image.**

Use any [sandbox image](/how-it-works/sandboxes/overview#sandbox-images) that
contains the agent and every tool it needs. The published OpenCode image
installs `opencode` at `/usr/local/bin/opencode`, so it works without a custom
build. Use an explicit version tag instead of `latest` for reproducible
deployments.

The built-in fallback policy grants access to the working directory and common
runtime paths, and denies network egress unless an attached provider contributes
an endpoint. Create a custom [sandbox policy](/how-it-works/policies/overview) when the
agent needs more filesystem access, package registries, source hosts, tool
servers, or other destinations.

**3. Create the sandbox.**

[Create the sandbox](/how-it-works/sandboxes/overview#create-a-sandbox), attach the
provider, and pass the agent command after `--`:

```shell
openshell sandbox create \
  --name my-agent \
  --from ghcr.io/anomalyco/opencode:latest \
  --provider anthropic \
  -- opencode
```

Add `--policy sandbox-policy.yaml` when the workload needs a custom policy. The
command after `--` becomes the sandbox's main process, and every child process
it starts remains inside the sandbox boundary.
